## 优先修复的问题

### 1. 普通页面可能完全没有收藏、分享和已读工具栏（P1，模板核对与模拟复现）

位置：`source/js/nuo-tools.js:68`；`themes/butterfly/layout/page.pug:14`；`themes/butterfly/layout/includes/header/index.pug`。

普通页面只在 `#page` 内寻找 `.page-title, h1`。有顶部图片时，主题把页面标题放在外部 `#page-site-info #site-title`，而不是正文内。正文没有一级标题的页面会返回 null，初始化提前退出；正文有一级标题时，又可能误把正文小标题当作页面标题。笔记入口就是带顶部图片、正文卡片使用 h2 的例子。

建议优先取主题真实页面标题，正文标题仅作后备。验收应覆盖带横幅/无横幅、正文有/无 h1，以及 PJAX 进入页面。

### 2. 阅读记录可能在切换页面时串写，监听也可能残留（P2，代码确认）

位置：`source/js/nuo-tools.js:153`、`:161`、`:327`。

250 ms 延迟回调捕获旧路径，却在执行时读取可变的 currentInfo。快速 PJAX 切换时，旧路径可能写入新页面元数据。进入书架、漫游或无法识别标题的页面时，会在调用清理函数之前返回；待执行定时器与旧滚动监听没有统一收尾。

建议保存时捕获完整页面快照，并在离开页面时保存/取消任务、移除监听和进度条。验收需要控制切换发生在延迟保存窗口内。

### 3. 笔记正文不记录阅读进度（P2，代码确认）

位置：`source/js/nuo-tools.js:135`。

进度逻辑要求存在 `#post`，而笔记走 `#page` 模板。即使修复标题识别，笔记仍无法记录进度。需要区分笔记正文与目录页，避免所有普通页面都被当成长文。

### 4. “继续阅读”只打开页面，不恢复保存位置（P2，功能缺口）

位置：`source/js/nuo-tools.js:373`、`:405`、`:413`。

清单根据保存比例展示未读完的文章，但链接没有携带恢复意图，页面初始化也没有读取进度并定位。建议采用“回到上次位置”的明确入口，图片加载完成后处理定位，并允许从头读。

### 5. 塔罗多牌阵中，牌面标记和解释可能互相矛盾（P1，模拟复现）

位置：`source/explore/tarot-app/index.html:142`，尤其 `:147`、`:154`。

渲染牌面和解释的两次循环，各自调用 Math.random 判定正逆位。相同牌可能显示“逆”，解释却采用正位。单牌不受此问题影响。

建议抽牌时一次生成 `{card, reversed}`，所有区域共享。验收覆盖三张和五张牌阵，逐牌比对标记与解释。

### 6. 2048 排行榜服务端报错仍显示成功并刷新（P2，模拟复现）

位置：`source/explore/game2048-app/index.html:252`。

fetch 对 HTTP 400/500 不会自动 reject，当前 then 不检查 response.ok，直接提示成功并 reload。建议检查状态和响应，失败时保留本局分数与昵称，允许重试。

### 7. 排行榜最大方块上传成总分（P2，模拟核对请求体）

位置：`source/explore/game2048-app/index.html:255`。

`maxTile: g.s` 与总分相同。应遍历棋盘取最大方块值；本轮未检查服务端是否使用该字段，因此不声称线上排名已经受影响。

### 8. 排行榜接口字段被直接作为 HTML 渲染（P1，前端危险路径确认，利用条件未核实）

位置：`source/explore/game2048-app/index.html:225`。

昵称、分数、日期直接拼入 innerHTML。若接口返回含标签或事件属性的字段，浏览器会按 HTML 解释。客户端输入长度限制不能替代输出安全处理；是否有服务端过滤尚未核实，不声称已发生攻击。

建议使用 textContent 构建列表，并校验数据类型。验收用无害的标签字符串确认它按文字显示，不向生产排行榜提交测试数据。

### 9. 2048 胜利提示与继续游戏不匹配（P2，重复提示模拟复现）

位置：`source/explore/game2048-app/index.html:65`、`:152`。

达到 2048 后设置 w=true，但下次判断没有检查 w，棋盘保留 2048 就再次弹出胜利提示。文案说可以继续挑战，遮罩却只有“再来一局”，没有明确继续按钮。

建议胜利仅提示一次，并提供继续游戏；仍须正确判断后续无路可走的状态。

### 10. 多次结束游戏会积累昵称输入框（P2，代码确认）

位置：`source/explore/game2048-app/index.html:238`、`:243`、`:167`。

每次结束都向同一遮罩追加带 `id=lb-input` 的节点；restart 只隐藏遮罩，没有清理。第二局结束会出现重复 ID，getElementById 可能读取第一局输入。

建议复用一个提交表单或在新局时清理，并防止结束后 300 ms 的旧回调插入新一局 UI。

### 11. 评测搜索无结果时保留旧统计（P2，模拟复现）

位置：`source/rate/index.md:186`。

renderAverageBarChart 在数据为空时直接 return。卡片虽已清空，均分和图表仍展示上一批结果，会把旧数据误认为当前筛选结果。

建议空集合时清除图表、均分显示“—”，并显示明确空状态。

### 12. 地图首次失败后，切换页签不能重新初始化（P2，代码确认）

位置：`source/js/rate-map.js:38`、`:163`。

loadPromise 和 initPromise 都被缓存，失败后没有重置。初始化异常被 catch 后，后续 ensureTravelMap 仍返回已缓存任务。第一次等数据超时后 resolve([]) 也会让空结果固定下来。

建议失败后允许重试，数据迟到时重新初始化；保留成功实例，避免重复创建地图。当前 SDK 超时计时从 onload 后才开始，也应覆盖脚本请求一直挂起的阶段。

### 13. 评测数据加载失败没有用户可见的错误出口（P2，代码确认）

位置：`source/rate/index.md:143`。

数据请求没有检查 HTTP 状态或 catch；请求失败、JSON 无效会中断初始化。建议展示加载失败与重试入口，并避免让筛选控件操作尚未加载的数据。

### 14. 评测后台允许保存缺坐标数据，与地图检查要求矛盾（P2，代码确认）

位置：`source/rate/admin/index.html:451`；`scripts/test-rate-map.js`。

空坐标或越界坐标会被转成 undefined，JSON 序列化后省略，但本地和云端保存仍会继续。地图检查则要求每个景点必须有有效坐标。现有 11 个地点检查通过，并非当前数据已损坏。

建议统一契约：要么保存前阻止无效坐标，要么明确允许“待补坐标”，并让页面与测试共同支持该状态。

### 15. 后台不填写 ID 时，重复保存会新增重复景点（P2，代码确认）

位置：`source/rate/admin/index.html:425`、`:284`、`:333`。

每次 generateJSON 都用当前时间生成新 ID，却未将 ID 固定回表单。同一条记录再次保存时会匹配不到旧项，转而插入新项。

建议创建表单记录时分配一次 ID，后续预览、保存、重试保持一致。显式“新建下一条”时才生成新 ID。

## 体验与工程完善

- 分享弹窗：`source/js/nuo-tools.js:282` 已实现初始焦点、Escape 和关闭后返回焦点，但没有 Tab 焦点约束或背景 inert，键盘能进入遮罩后的内容。（P3）
- 探索区 10 个嵌入应用的 iframe 没有 title，辅助技术难以辨认内容。可按具体应用补充。（P3）
- CI 已执行牌数据、阅读工具语法和构建，但没有执行已有的 `test:map`。当前牌数据测试也只检查非空数组，不覆盖牌阵渲染；“测试通过”不能排除上述业务缺陷。（P3）
- 搜索只索引 post；笔记入口只筛标题/描述，不搜索章节正文。这是现有能力边界，可作为新功能需求，不必与运行错误混在一起。

## 新功能建议，独立于修复清单

1. 笔记全文搜索：按课程与章节筛选，展示命中片段；仅索引明确公开的内容页，排除后台、原始应用资源和不应被索引的内容。
2. 统一续读：修复标题、生命周期和笔记进度后，再补回到上次位置。
3. 阅读清单导出/导入：迁移浏览器本地数据；导入时检查结构、站内链接和重复记录。
4. 有范围的随机漫游：只看未读、按内容类别选择，保留全站随机选项。
5. 2048 棋盘存档：保存当前局，继续或主动开新局。
6. 长问卷可选暂存：用户主动开启本地保存，提供清除入口。
7. 探索页分类链接：分类写入 URL，支持分享及浏览器前进后退。

## 建议执行顺序

先处理 P1 的标题识别、牌阵一致性和排行榜安全渲染；随后按模块修复阅读生命周期、2048 提交与结束流程、评测空状态及数据契约。完成后再新增全文搜索或续读，避免在有缺陷的状态管理上继续叠加功能。
