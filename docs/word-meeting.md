# 词意同遇

入口为探索 → 小游戏 → 词意同遇，页面 `/explore/word-meeting/`。独立页面保留返回探索入口，参考用户提供的词卡与联想轨迹截图制作，支持手机、深色模式和键盘输入。

## 设计

以双词逐步相遇作为视觉重心，双词卡并排、下方接逐轮轨迹，不加入排行榜或分数。颜色采用纸白 #FFF9F7、浅粉 #F7E4DF、薄荷 #D6F2E5、墨色 #292B2A、叶绿 #246A51；标题与词语使用系统宋体，操作和状态使用系统黑体。手机保留双栏词卡，输入区单行提交；深色模式和减少动态效果偏好均有对应样式。已检查手机、桌面和深色截图。

## 玩法

第一轮两人各自想一个词。每个人的词提交后锁定，服务器在双方都提交前不返回任何人的本轮词语。两人都提交后同时揭晓：相同即结束；不同则各自从上一轮两个词寻找关联，双方准备后进入下一轮，直到想到同一个词。关联由玩家自行判断，不请求AI，也没有倒计时。

匹配忽略空白、字母大小写和NFKC兼容字符差异（如全角英文字母），不擅自把同义词、简繁体或不同标点判断成同一词。词语最长32个Unicode码点；称呼最长12个。

- 邀请朋友：创建房间后分享8位房间码或邀请链接，对方使用另一台设备加入，无需注册。已满房间不接受第三位玩家。
- 同屏轮流玩：不需要网络，第一位锁定后隐藏输入，交接界面提示把设备交给另一位。双方提交后揭晓。设备持有人仍能通过开发者工具查看本机状态，这不是安全隔离设备。
- 每轮显示上一轮的两个词，并保留已揭晓记录。相遇后可下载UTF-8文本记录；联机再开局会新建房间，需要分享新的邀请。
- 同一标签页刷新可恢复当前身份和状态；本局词语、准备状态由服务端确认，失败保留输入。页面重新可见时刷新；联机期间约2.5秒检查一次更新，隐藏或离开页面停止轮询。

## 服务端与私密性

复用 `workers/comments` Worker 和现有 D1，不依赖Clerk登录，也不新增第三方服务或密钥。迁移 `0012_word_meeting.sql` 新建 `word_meeting_rooms`、`word_meeting_rounds`。

客户端用Web Crypto生成256位随机入场凭证，存入sessionStorage；API只保存SHA-256摘要。凭证不进入邀请链接、公开房间信息、历史记录或下载内容。猜到房间码的人可能占据尚空的第二个位置，因此请私下发给朋友；游戏未提供旁观、公开房间列表或公共战绩。

房间有效期为创建后24小时，过期接口拒绝访问。每次创建房间时清理已经过期的房间及其词语。因而24小时是可访问期限，不承诺精确到秒物理删除；若没有新房间创建，过期数据会暂留数据库中。现有限流表只新增短期计数，不保存完整IP；创建/加入的限流键由服务端IP哈希生成。

SQL条件写入和D1 batch事务保证单方提交不可改词、两人并发不会跳轮、旧轮请求不能覆盖新轮。只有双方已揭晓且都准备好才能推进。词语及昵称按普通文本渲染，不使用用户内容拼接HTML。

## 接口

基础路径 `/v1/word-meeting/rooms`，沿用现有CORS站点限制。

| 请求 | 内容 |
| --- | --- |
| `POST /` | `{name,token}` 创建房间，返回玩家a的状态 |
| `POST /<code>/join` | `{name,token}` 加入房间，相同凭证可重试恢复身份 |
| `GET /<code>` | 使用 `Authorization: Bearer <token>` 读取自己的视图 |
| `POST /<code>/submit` | 同上凭证及 `{round,word}`，锁定本轮词语 |
| `POST /<code>/next` | 同上凭证及 `{round}`，准备进入下一轮 |
| `POST /<code>/leave` | 同上凭证及 `{}`，结束本局 |

状态包含 `phase`（waiting/thinking/revealed/matched/closed）、`round`、`you`、双方称呼和提交/准备标记。`words` 在双方提交前为null，`history` 只含已揭晓轮次。没有接收玩家ID、指定对方身份或客户端自报相遇结果的接口。

## 验证与发布

- `npm test --prefix workers/comments`：后端测试包含房间私密性、第三人、过期、限制、重试、双人准备、并发和匹配。
- `npm run test:word-meeting`：真实Worker逻辑与本地SQLite、三个隔离浏览器会话，验证两端揭晓、刷新、断网保留、下载、同屏交接、文本注入和360px布局；不向生产创建测试房间。
- `npm run build`：检查探索入口、独立游戏页和资源输出。
- 截图输出到 `test-results/word-meeting-{desktop,mobile,dark}.png`。

发布顺序：先 `npm run migrate --prefix workers/comments` 应用D1迁移，再 `npm run deploy --prefix workers/comments` 发布接口，最后提交推送GitHub由Vercel更新页面。同屏玩法只依赖静态资源，联机需要以上后端步骤完成。游戏接口发布前无需修改Clerk应用或提供API Key。
