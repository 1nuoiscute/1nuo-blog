# 账号书架与 2048 排行榜

收藏、阅读进度、已读状态与评论共用 Clerk 会话，使用现有 `1nuo-blog-comments` Worker / D1。无需额外 API Key。书架入口仍为 `/favorites/`；2048 仍可匿名游玩，只有主动提交榜单需要登录。

## 书架

- `GET /v1/library`、`POST /v1/library` 均要求登录；所有权只取已验证的 JWT `sub`，不接受客户端指定其他用户。
- 收藏、进度、已读分别保存，互不覆盖。每条记录由站内路径识别，保存标题、类型与对应状态，不上传正文、完整浏览历史或阅读模式偏好。
- 各设备按操作时间合并，同一时间用操作 ID 稳定排序；取消收藏保留删除标记，避免旧设备重新同步时复活。极端错误的设备时钟仍可能影响先后顺序，不是多人实时协作协议。
- 当前账号缓存与待同步操作按用户隔离。提交后约 6 秒、恢复网络、重新打开页面及页面可见时同步；可见页面每分钟也会检查一次。关闭时未发完的操作留待下次打开继续。
- 新设备首次连接先读取云端，再恢复「继续阅读」位置。切换账号先保存旧账号的当前进度，迟到的旧响应不会写入新账号。
- 游客继续使用原来的本地记录。书架的「导入此设备原有记录」由用户主动触发，合并进当前账号，保留原本地副本；已有云端记录和删除标记优先，不会自动分配给某个注册账号。
- 最近浏览只留在本机，并按登录账号隔离；退出后回到游客本地视图。
- 每次同步最多 10 条，客户端分成 5 条一批；每个账号每分钟最多 60 次写入，最多保存 5000 条状态（含删除标记）。大量旧数据导入可能分多轮完成。

## 2048

- `GET /v1/leaderboard/2048` 可匿名读取前 50 名，登录时同时返回自己的最佳成绩。
- `POST /v1/leaderboard/2048` 要求登录，每个账号只保留一个最佳成绩；低分不会覆盖高分，相同分数比较最大方块。每账号每分钟最多 5 次提交。
- 昵称、头像来自前端读取的 Clerk 展示资料；允许用户自行修改展示名，唯一身份始终是 JWT 用户 ID。公开结果不返回用户 ID，所有文本均按普通文字渲染。
- 这是休闲榜：服务器校验数值、所有权、频率和最佳成绩，但成绩仍由客户端上报，没有服务器复盘或赛事级反作弊。不要将此榜当作可信竞赛排名。
- 切换账号后，已结束的旧账号对局不能转投新账号；开始新一局后再提交。失败保留本局数据，成功按钮禁用，避免重复点击。
- 旧 `status.1nuo.me` 匿名榜保留在「历史匿名榜」中，仅读取展示，不按同名昵称自动认领，也没有迁移或冻结旧服务的写接口。
- 复用父页面账号服务；独立访问游戏时也能加载同一 Clerk 配置。游戏局面、撤销记录和其他小游戏存档仍是本地数据，本次不做云存档。

## 验证与部署

`npm test --prefix workers/comments` 使用 SQLite 和本地签名令牌验证账号隔离、字段校验、删除合并、最佳成绩与限流。`npm run test:cloud` 用模拟账号/API 和两个独立浏览器设备验证同步、离线重试、导入、切换账号、续读和排行榜。测试不向生产库写入测试收藏或分数。

先运行 `npm run migrate --prefix workers/comments` 应用新增迁移，再 `npm run deploy --prefix workers/comments` 发布接口，最后推送 GitHub 由 Vercel 发布页面。沿用 `ALLOWED_ORIGINS` / `CLERK_ISSUER` 的正式站点限制；Clerk 转正式实例时仍需统一处理开发账号与正式账号 ID 的变化。
