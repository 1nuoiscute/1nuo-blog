# 讨论区

入口 `/discuss/`，导航「讨论」。详情链接使用 `/discuss/?id=<UUID>`，刷新、分享和登录跳转都保留帖子编号。页面由 Hexo 发布，帖子和回复通过现有 Worker / D1 动态读取。

## 功能

- 游客浏览已发布帖子，登录后发帖、回复、查看自己的帖子。
- 分类：随便聊聊、问题交流、网站反馈；按最新回复或最新发布排序，每页 20 条。
- 标题 100 字、正文 6000 字。正文与预览支持段落、三级标题、列表、引用、代码块、行内代码、粗体和链接。
- 草稿按账号和帖子分别保存在本机；切换账号立即收起编辑器，失败保留草稿；发布使用唯一编号，重试同一次提交不会生成重复帖子。
- 作者编辑、删除自己的帖子。编辑携带版本号，旧版本返回冲突；普通用户编辑后重新审核。
- 回复审核通过后获得固定楼层号，楼内回复会注明所回复的楼层；隐藏、删除及分页都保留原编号。
- 帖子与回复支持账号点赞、取消点赞，列表同时展示帖子赞数和公开回复数。
- 管理员在讨论区「管理」查看待审核、已发布、已隐藏的帖子，进入详情后发布、隐藏、置顶、关闭回复、删除或 AI 复审。回复沿用 `/comments-admin/`，队列中的讨论地址可点击进入帖子。

## 页面设计

沿用站点字体与账号配色：白色 `#fff`、淡粉 `#fff8fb`、正文 `#29252b`、辅助文字 `#746973`、分隔线 `#eedee6`、主按钮 `#ae4778`。深色模式使用账号页共享变量。

```text
讨论                         [发起讨论]
一句介绍
全部  随便聊聊  问题交流  网站反馈   我的帖子 / 排序
头像  标题与摘要                         回复数
      分类、作者、时间
─────────────────────────────────────────────
```

主题列表采用一条内容流，头像和回复数作为定位点；手机上将筛选和排序分行。详情以正文为主，管理操作放在文末。

## 数据与权限

迁移 `0006_discussions.sql` 新增 `discussions` 表。帖子所有权取已验证的 Clerk JWT，昵称和头像保存发布时的展示资料。公开响应不返回账号 ID。

- `GET /v1/discussions`：公开列表；可带 `category`、`sort=active|new`、`offset`。
- `GET /v1/discussions?mine=1`：当前账号的帖子，包含待审核与已隐藏状态。
- `POST /v1/discussions`：发布，携带 `title/body/category/requestId/name/avatar`。
- `GET/PATCH/DELETE /v1/discussions/<UUID>`：详情、作者编辑、作者或管理员删除。
- `PATCH /v1/discussions/<UUID>`：管理员通过 `state/pinned/locked` 管理，和正文编辑分开提交。
- `GET /v1/admin/discussions?state=pending|published|hidden`：管理列表。
- `POST /v1/discussions/<UUID>/moderate`：管理员 AI 复审。
- `POST/DELETE /v1/discussions/<UUID>/like`、`/v1/comments/<ID>/like`：点赞、取消点赞，重复提交保持同一状态；返回赞数和当前账号是否已赞。

迁移 `0007_likes_floors.sql` 为历史已发布回复补齐楼层，后续首次发布通过数据库触发器分配。讨论回复分页使用 `楼层:回复ID` 游标；普通文章评论仍使用 ID 游标。点赞按内容和 Clerk 用户 ID 唯一存储，每账号每分钟最多 90 次操作。公开接口只返回总数和当前账号的点赞状态。

回复沿用评论表，线程固定为 `/discuss/<UUID>`。读写回复先验证帖子可见性；写入还检查帖子已发布且开放回复。隐藏、待审核或已删除帖子的回复不会通过游客接口返回。

DeepSeek 审核同时查看标题与正文，与评论共用每日预算（当前配置 100 次）。普通帖子先待审核，管理员发帖直接发布；人工处理、删除或更新内容会让旧审核结果失效。

Markdown 通过 DOM 节点构建，用户输入不进入 HTML 解析器。链接允许 HTTP/HTTPS，外链带 `nofollow ugc noopener noreferrer`。首版以文字交流为主；通知与关注作为后续功能。

## 验收与发布

`npm test --prefix workers/comments` 验证身份、可见性、编辑冲突、审核竞态、幂等、分页及关闭回复；`npm run test:discuss` 使用隔离账号和接口测试发帖、回复、草稿、切换账号、管理、PJAX、手机和深色模式。测试不向正式服务发布内容。

先应用 D1 迁移并部署 Worker，再推送页面由 Vercel 发布。
